# spw-folia v0.4.15 更新日志

> v0.4.14 发布后收到的两个问题，都在这版修好了：
> **① 第一次打开设置，几秒后面板自己退出；② 点「反馈」打开的网页报错打不开。**

---

## 一、修好了：第一次打开设置，几秒钟后自动退出

### 现象

刚打开播放窗口时点齿轮（或首次自动弹出）进入设置，**等几秒钟，设置面板会自己消失**，
回到播放页面。之后再打开就正常了，所以只有第一次特别明显。

### 原因（已完整定位并实测确认）

插件把设置界面注入到 Folia 的页面里。这个设置界面被**加载了两次**：

- 宿主注入时用的地址带版本号：`settings-ui.js?v=0.4.15`；
- 而设置界面内部那些较晚加载的样式模块，回头引用入口文件时**没有带版本号**：
  `settings-ui.js`。

浏览器按**完整地址**区分模块，所以「带版本号」和「不带版本号」被当成两个不同的文件，
各执行了一遍。第二遍执行时，它发现页面上已经有设置界面的容器，就**接管了同一个容器**
——于是第一遍已经渲染好的界面被整体卸载掉了，看起来就是「自己关掉了」。

它需要几秒钟才发生，是因为要等样式预览把第一张图渲染出来、Pixi 把着色器链好之后，
那批回头引用入口的模块才被加载 —— 所以**第一次打开最慢、最明显**。

### 修复

加了三道防线（任一道都足以阻止，同时保留是为了防回归）：

1. 挂载前检查 `window` 上的**全局标记**（模块作用域在两次加载之间不共享，只有 `window` 共享）；
2. 注册控制器时用**所有者标记**，第二个实例不能抢走 `__SPW_FOLIA_UI__`；
3. 已经带 React root 的容器**拒绝再次 `createRoot`**。

### 验证

- 真机日志确认：第二遍加载被拦住，只报一行 `settings UI already mounted by another instance`；
  面板 `open` 1 次、`closed` **0 次**（修复前是 2.4 秒开后 0.8 秒即关）。
- 门禁新增 3 条守卫，其中一条会扫描打包产物里全部 44 处反向引用；
  把防线拆掉后门禁立刻 FAIL（已实测），所以这个 bug 不会悄悄回来。

## 二、修好了：点「反馈」打开的网页打不开

### 现象

在设置里点反馈按钮，浏览器打开 GitHub 后显示 **「Whoa there! Your request URL is too long.」**。

### 原因

反馈链接把整份环境报告塞进了网址里。原来的上限是**按字符数**算 6000 ——
但正文是中文，百分号编码后**一个汉字占 9 个字符**（`问` → `%E9%97%AE`），
所以 6000 字的中文正文会变成约 **15000 字符**的网址，远超浏览器/GitHub 的上限。

顺带发现：如果正文里有 emoji，原来的截断方式还会让代码直接抛异常。
这两处都已修。

### 修复

改为按**编码后的实际长度**截断（中英混排时安全长度从 820 到 7380 字符不等，
所以任何「按字符数」的上限都不可能正确）。截断不会切断半个编码单元，也不会把 emoji 切成两半。
上限 6000，实测各种输入（纯中文 / 纯英文 / 中英混排 / emoji）的最终网址都在 6060 字符左右。

同时补了测试：原来的用例只断言「网址短于 15000」，那个宽松阈值恰好放过了 15162 的错误网址。

## 安装 / 升级

1. 下载 `spw-folia-0.4.15.spmod`；
2. 放到 `%APPDATA%\Salt Player for Windows\workshop\plugins\`；
3. 打开 SPW → 模组管理 → 启用。

**装过旧版请先删掉再装** —— 同 id 的多个版本不要并存。

**升级不会丢设置。** 之前的设置会自动迁移，包括挪过位置的「详细日志」。

## 附：门禁现状

`verify-all.mjs` 现为 **21 项**（v0.4.13 时代是 10 项），其中：

- **47 个 JVM 单元测试**（配置失败路径、诊断四态、JSON 解析）；
- **4+3 条守卫**：配置同步不得自我递归、重试上限必须是常量、必须有深度兜底、
  不存在孤立验收脚本、设置界面必须防重复挂载、控制器不能被抢占、每个分块反向引用必须被守卫；
- 6 个真实宿主 + WebView2 套件。

每一项都验证过「能被真正的缺陷触发失败」，而不是恒真。
