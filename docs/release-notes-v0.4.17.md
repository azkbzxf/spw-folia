# v0.4.17 更新日志

本次版本修掉 issue #18 的四项已知问题。

## 1. 凝彩样式失效（已修复）

**现象**：选「凝彩」后整屏只剩噪点/色斑，看不到歌词。

**原因**：Folia 0.7.25 给凝彩新增了三个参数（景深 `depthOfField`、镜头平移 `depthPan`、字形纵深
`glyphDepth`）。插件把用户的设置树原样下发给渲染器，而渲染器**不会**补齐缺省的键 —— 老用户与本机
缓存里的设置树是在这三个参数出现之前存的，于是渲染器拿到 `undefined`，参与坐标运算后变成 `NaN`，
整个构图被算没了，只剩背景层。

**修复**：设置树读取改成「**默认值打底 + 用户保存的值覆盖**」，逐样式合并；下发渲染器之前再兜一层默认值。
这样无论旧设置树缺哪些新参数，渲染器拿到的永远是完整的一袋。

顺带修掉同类隐患：任何样式将来新增参数都不会再复现这个问题；设置树里出现本版本不认识的样式
（更新版的页面写的）也不会再被丢掉。

## 2. 「显示播放条」搬进播放页右下角菜单（已实现）

以前这个开关在 SPW「模组管理 → 配置」页；现在它就在**播放画面右下角那个按钮点开的面板里**，
一行开关，改完立刻生效，和「播放页透明背景」放在一起。

- 关闭后底部播放条**整个不绘制**（连点击热区一起消失，不会留下点不到的死区）。
- 关掉之后**那个右下角按钮仍然在**，随时能再打开 —— 不会把自己锁死。
- 老用户升级：以前在配置页关掉过的人，升级后播放条仍然是关的（迁移一次，之后由页面自己记住）。

配置页「播放页」一组里不再有这一项，剩下「打开过渡动画」「歌词样式预览动画」「显示问题反馈按钮」。

## 3. 点「出现问题」打开的是「文档」而不是日志文件夹（已修复）

**现象**：点「出现问题」，弹出的是「文档」文件夹。

**原因**：插件启动资源管理器时把「打开并选中日志文件」的开关（`/select,`）和日志路径拼成了**一个参数**。
Java 在所有含空格的参数外面自动加双引号 —— 而插件的安装路径默认就含空格
（`...\Salt Player for Windows\workshop\plugins\...`），于是资源管理器收到的是一个前面带引号的
怪参数，认不出来，退回自己的默认起始位置（文档）。**路径里没有空格时反而正常**，所以很容易漏掉。

**修复**：开关和路径分成两个独立参数，资源管理器就能正确解析。已验证：落点是日志所在目录，
并且日志文件处于选中状态；路径含空格、逗号、`&`、`%`、`!`、`^`、`#`、中文、超长路径全部正常。

## 4. 点画面中央暂停、点左右两侧切歌（已实现）

播放画面上新增一层透明点击区，横向三份：

- **中间**：播放 / 暂停
- **左侧**：上一首
- **右侧**：下一首

细节：
- 不会抢底部播放条、右下角按钮、右上角按钮的点击 —— 那一层在所有控件**下面**。
- 拖动（按下后移动超过约 10 像素）不算点击，不会误触发。
- 设置面板打开、或开着鼠标穿透时不生效。
- 这一项**不依赖**「显示播放条」：即使把播放条关掉，点画面中央照样能暂停。

- 日志文件夹：真实启动资源管理器并读回窗口位置**与选中项**；同时用旧版写法做负面对照，证明这个检查
  真的会红（旧写法落点是「文档」）。

- 点画面：真实点击三个区，抓到宿主收到的 `toggle` / `previous` / `next`；40 像素拖动确认一条都不发。
