# v0.4.18 更新日志

本次版本修掉 issue #19 的两项：点击分区与「町景」拖动旋转的冲突，以及宣传站重做。
另外清理了一批过时的验证脚本。

## 1. 点画面暂停/切歌 与「町景」拖动旋转 不再打架（已修复）

**现象**：v0.4.17 加了「点画面中间暂停、点左右两侧切歌」之后，「町景」画面上**按住拖动不再能转动
场景**，滚轮不能缩放，右键拖动也不能平移。同样的原因也让「莫奈」的挂绳拖不动、歌词条滚不动。

**原因**：那层点击区是 `pointer-events: auto` 铺满整窗口的。它成了画面上**每一次按下**的命中目标，
下面的画布再也收不到 `pointerdown`。「町景」的拖动旋转、滚轮缩放、右键平移全部由挂在画布上的
three.js `OrbitControls` 驱动，而 `OrbitControls` 正是从画布的 `pointerdown` 开始整套手势状态机的 ——
源头上就断了。v0.4.17 的实现还按 z-index 排序，思路是「控件在上面就赢」，但画布是一个 `pointer-events`
自己开着的兄弟层，它不在那个 z-index 竞赛里。

**修复**：把这层从「拦截层」改成**幽灵层**——

- 它自己不再接收任何指针事件（容器与三个子元素都是 `pointer-events: none`），画面照常拿到自己的那一份；
- 判定挪到 `window` 的**捕获阶段**：捕获阶段从 window 往下走，因此它比画布**先**看到这次按下，
  而画布随后仍然收到自己那份 —— 两边都赢；
- `OrbitControls` 会在画布上 `setPointerCapture`。指针捕获只是把后续指针事件**重定向**给画布，
  并不缩短传播路径，所以 window 捕获仍然收得到整个手势的 move / up。

同时补上两条 v0.4.17 漏掉的规则：

- **非指针事件也归画面**：滚轮与右键菜单原来的命中目标是那层 div，永远到不了画布。现在它们直接落到画布。
- **裸 `div` 的拖拽也认**：「莫奈」的挂绳是一个只有 `cursor: pointer` 的 `div`，没有标签、没有 role、
  没有属性，选择器抓不到。所以除了标签 / ARIA role / 本岛自己的类名，还看**祖先链的计算 cursor**：
  按下点落在 `pointer` / `grab` / `move` / `*-resize` / `zoom-*` 这些「我要指针」的样式上，就不算画面点击。

保留的语义（与 v0.4.17 相同）：

- 左中右三等分：上一首 / 播放暂停 / 下一首；
- 位移超过约 10 像素、手势取消、按住 Alt（宿主窗口拖动）都不算点击；
- 设置面板打开、鼠标穿透、右下角菜单 / 反馈面板 / 字体选择器打开时整层失效；
- 从控件上按下的手势完全不归点击区管（播放条、右下角按钮、右上角 ⚙、队列面板都是）。旧的
  z-index 竞争没有了，因为已经没有层可争。

**注意**：「町景」画面中间**单击**仍然是暂停 —— 这是 v0.4.17 的既定语义，issue 只要求拖动不再被吃。
现在按住拖 → 相机转、不发任何播放指令；原地单击 → 恰好一次暂停。

## 3. 清理过时的验证脚本，门禁改为按范围执行

删掉 17 个已经没人引用、也不再描述现状的一次性脚本（4 个 settings-ui 侧的子文档布局探针、
fidelity 采集三件套、Folia 原版 UI 对照、task-11 时期的 `shot.mjs` / `check-reset.mjs`、
两个零引用的 webview 服务器探针等）。它们在 Git 历史里都还在。

同时删掉 9 个「覆盖区域早已稳定」的门禁脚本（splash 契约、透明窗口 HUD、侧键返回、
tuning 合并、预览动画开关、行协议单行、配置页开关链路、旧版 control/queue 全链路、v0.3.0 遗留项）。

更重要的是 `verify-all.mjs` 本身改了：以前**每次发布都全量刷 24 项**，其中大半在重复证明十来个
版本都没动过的东西 —— 又慢又吵，久而久之就会被当成走过场。现在按改动范围分四个 scope：

| scope | 覆盖 | 何时跑 |
|---|---|---|
| `core` | 版本三处一致、声明⇄读取双向、无重复键、无孤儿门禁脚本、JVM 配置失败路径 | **总是**（便宜，且是用户无法自行恢复的失败） |
| `page` | 点击分区/幽灵层、播放条开关、问题按钮开关、设置树端到端 | `poc/settings-ui/src`、`poc/webview/**` 被改时 |
| `plugin` | 自检、「出现问题」日志落点 | `spw-folia/**` 被改时 |
| `layout` | 打包件真机冒烟 | `packaging/**` 被改或出包时 |

三条不能让底线松掉的规则：

- **跳过 ≠ 通过**：未选中的项打印 `SKIP` 并给出原因，摘要固定输出
  「N/M executed checks (K skipped)」——「绿」永远意味着「这么多项真的跑了且过」；
- **门禁必须有牙**：删完之后注入真实回归（把 window 捕获监听从 `true` 改成 `false`）验证它确实
  会红 —— 9 项失败，不是空跑；
- **无孤儿**：`core` 里有一条 `no orphaned verify-* scripts`，新增脚本没接进 `SUITES` 就 FAIL。

发布前跑一次 `--all` 走全范围，日常改动跑默认范围即可。

## 验证

本版本的两项都跑在**真实宿主 + 真实页面**上：

**点击分区 / 町景拖动**（`.scratch/probe-issue19-zones.mjs` 等三份探针，共 106 项）：
- 中间三分之一 `elementFromPoint` 是 `CANVAS`，不再是点击区；三个子元素仍在 DOM、仍是三等分；
- 三等分各单击一次 → 宿主 stdout 恰好一条 `toggle` / `previous` / `next`；
- 40 像素拖动 → 零条播放指令；
- 画布确实收到 `pointerdown`、`OrbitControls` 确实跑到 `setPointerCapture`、window 捕获确实看到同一次手势；
- 播放条按钮、右下角菜单、进度条 seek、队列点选都只发自己那一条，不会被点击区多带一条；
- 设置覆盖层打开 → 整层失效且不发指令，关闭后恢复。

**真实鼠标终验**（`.scratch/probe-issue19-realmouse.mjs`，user32 级输入，13 项）：
- 真实拖 300 像素 → 画面变化量 46.7，空闲基线 0～3.7（**相机真的转了**），且**零条**播放指令；
- 三等分真实单击 → 各恰好一条；播放条的播放键、右下角菜单按钮各自只做自己的事；
- 每项都带**前置条件断言**：先断言播放条已展开、按钮可命中，再点 —— 否则「恰好一条 toggle」
  可能是点在画面上得到的假通过。

**宣传站**：`node site/tools/check-site.mjs` → 83/83 PASS。

**发布门禁**：`node packaging/tools/verify-all.mjs` → 13/13 executed checks（按本次改动自动选
`core`+`page`+`plugin`+`layout` 四个 scope；57 项 JVM 单测全过）。
