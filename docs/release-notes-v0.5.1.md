## 一、修好了：更新提示没有真的「只弹一次」

### 现象

装上 0.5.0 之后，每次重启 Salt Player，底部都会再弹一次：

> 模组 spw-folia 已更新至 0.5.0 版本（重要更新）

而我们承诺的是**只弹一次**。

### 原因（已定位到具体一行）

标记其实**已经正确写进了磁盘**：

```json
{ "updateNoticeShownVersion": "0.5.0", "settingsJson": "…" }
```

但读取走错了地方。代码读标记时用的是宿主给的配置对象（`ConfigHelper.get`），而它返回的是
**进程内的内存视图**，这个视图可能比磁盘旧 —— 于是读到的值是「没有」，判定成「从没提示过」，
就又弹了一次。写入是对的，读取是错的。

> 这个坑在本项目里**不是第一次出现**：v0.4.12 重写配置同步时就是因为同一类问题
> （宿主 `getConfig()` 返回缓存）才改成「把磁盘文件当唯一事实来源」。这次写更新提示时没沿用那条纪律。

### 修复

读取改成**直接解析磁盘上的配置文件**（`getConfigPath()` 拿到路径，再读原始 JSON 文本），
和配置同步用同一套做法。写入之后还会**回读校验一次**，确认真的落到盘上了才算成功。

### 验证

- 新增回归测试 `a stale in-memory helper view cannot resurrect the notice`：让配置对象带着
  **缺少该键的陈旧视图**、而文件里已有标记 —— 读取必须返回 `0.5.0`、判定必须是「不弹」。
- 把读取改回内存视图，**4 条测试立刻失败**（含上面这条）；改回磁盘读取，复绿。
- 真机复验：标记存在时重启 SPW，日志为
  `update notice: skipped (version=0.5.0 noticed=0.5.0)` —— **不再弹**。
- JVM 单测 72 项全过；发布门禁 `verify-all.mjs` **10/10**。

### 还想要那条提示怎么办

不用做什么。**0.5.1 自己不会弹这条提示**（它只属于 0.5.0 那一次）。

如果你从没看到过它（比如 0.5.0 弹出时你不在屏幕前），也不必担心 —— 它本来就是个提示，
不是功能入口。想确认更新成功了，看「模组管理」里的版本号即可。

## 附：给维护者的技术备注

**缺陷归属**：0.5.0 的 `FoliaUpdateNotice.readNoticedVersion` 用 `config.get<Any?>(KEY, null)`
读标记。宿主的 `createConfigManager().getConfig()` 返回的 helper 携带的是**进程内快照**，
在插件启动早期可能尚未反映磁盘内容，`get` 落到默认值 `null` → 与「从未提示」不可区分 → 重复弹。

**修复**：`readNoticedVersion` 改为 `helper.getConfigPath().toFile().readText()` +
`Json.stringField`，与 `FoliaConfigSync.readConfigText` 同一纪律（磁盘是唯一事实来源）。
`writeNoticedVersion` 在 `save()` 之后**回读校验**，返回 false 时调用方不写「已完成」状态。

**为什么原测试没抓到**：初版测试用的 `InMemoryConfig` 是 **map 支撑**的假 helper，而生产读取已改为
文件路径 —— 假实现测的是一条生产不存在的路径。现在假 helper 改为
`FileConfig`（拥有真实临时文件，且刻意保留一个**故意陈旧**的 `get` 视图），
新用例才能覆盖「文件有值 / 内存视图没有」这个真实形态。

**门禁盲区**：`verify-all.mjs` 只驱动打包页面，不驱动插件启动时序，所以它对这个 bug
**永远不会红**。这类「一次性副作用 + 持久化标记」的正确性只能靠单测钉住读取语义 +
真机复验重启路径。教训已补进 `docs/lessons.md`。
