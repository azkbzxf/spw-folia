# spw-folia v0.4.13 更新日志

> **这是 v0.4.6 之后第一次正式发布。** 中间做过很多版但都没发出去，所以这一版把那些改动
> **一次性全部带给你** —— 下面按「你会看到什么」来写，不按版本号。

---

## 一、先看这个：修好了三个开关

之前有一版把配置页的三个开关弄坏了：**开关打开了，但功能没反应**。

| 开关 | 现在的效果 |
| --- | --- |
| 打开过渡动画 | 打开 Folia 时有开屏动画 |
| 显示播放条 | 播放页底部有播放控制条（时间轴 / 播放暂停 / 上下首 / 随机 / 播放列表） |
| 显示问题反馈按钮 | 播放页右上角出现救生圈按钮 |

现在三个都正常了，而且**改了立刻生效**，不用关掉窗口再重开。

> 其中「打开过渡动画」和「详细日志」这两个是下次打开 Folia 时才生效的，因为它们决定窗口怎么被打开。

---

## 二、两个新歌词样式（15 → 17）

跟着上游更新一起加进来的：

- **町景** —— 三维微缩街景，歌词写在便利店 LED 屏和招牌上。有便利店 / 车站 / 城寨三套场景，时间、天气、镜头都能调。
- **雾笺** —— 雨夜公交车上起雾的车窗，歌词按笔顺一笔一笔写出来，写过的笔画露出窗外夜景，水珠顺着笔画淌下来。

---

## 三、开屏动画换成了原版的

之前是我们自己做的一段过渡动画（封面取色渐变、极光、余烬、光扫那一套），现在换成 **Folia 原版的开屏**：
深色底 + 居中发光的「Folia」字样 + 一排随机跳动的波形竖条。

顺便修了两个问题：
- 原来开屏会多停留约 1 秒，现在准时消失；
- 开屏上的字原来会随机换字体，看着像坏掉了，现在固定一种。

---

## 四、透明模式不再一片粉

如果你用过「透明播放器背景」，可能见过画面上糊一层**粉色**。

原因不是背景色选错了，而是透明模式下那些**半透明的地方**（比如字的边缘）会被染色。换了一个几乎看不见的
底色之后，粉色彻底消失了。

---

## 五、配置页重新整理了

以前配置项混在一起，现在按「你什么时候会用到它」分成三组：

| 分组 | 放什么 |
| --- | --- |
| **播放页** | 打开过渡动画、显示播放条、显示问题反馈按钮 |
| **诊断与日志** | 详细日志（平时不用开，排查问题才用） |
| **支持与反馈** | 出现问题（打不开播放窗口时也能用） |

新增的「显示问题反馈按钮」**默认是关的**，因为它会挡在画面右上角。

---

## 六、设置界面的两个小毛病

- **预览框一片空白** —— 修好了；
- **样式小图显示成破图** —— 修好了。

另外样式选择那里，小图现在不再是一张张静态截图，而是**真的在跑**：鼠标停在某一格上才会开始动，
同一时间只有一格在动，不占性能。

---

## 七、删掉了「帧率」设置

配置页原来有个帧率选项，已移除 —— 它会让画面变卡却不明显，容易让人以为是别的问题。

---

## 八、其它

- 修好了「出现问题」自检工具在正常电脑上乱报错的问题（现在分成「通过 / 有问题 / 不知道」三态，每条都能复核）。
- 托盘图标、快捷键、播放控制这些日常功能与以前一致。

---

## 安装 / 升级

1. 下载 `spw-folia-0.4.13.spmod`；
2. 放到 `%APPDATA%\Salt Player for Windows\workshop\plugins\`；
3. 打开 SPW → 模组管理 → 启用。

**升级不会丢设置。** 之前的设置会自动迁移过来，包括「详细日志」这种挪过位置的开关。

## 附：给维护者的技术备注

上面是面向用户的内容。以下仅供排查问题参考。

**本版修复的两个独立缺陷（v0.4.12 引入）：**

1. **行协议被换行截断（主因）**：插件与辅助进程之间是行协议（插件写 `line + "\n"`，辅助进程用
   `ReadLine()` 读），而 `settings` 消息把设置树原样内嵌进一行。内置 `default-settings.json` 是美化
   格式（7188 字节 / **268 个换行**），一条推送被拆成几百条非法 JSON 片段全部丢弃，页面从未收到
   `showPlaybackBar` / `showProblemButton`。修复前宿主日志里插件下发的 settings 是 **0 条**。
   修复：`Json.singleLine()` 在发送前压成单行（字符串字面量内容逐字节保留），`sendSettings()` 在
   统一出口调用。

2. **`ready` 之前的推送被丢弃且从不重发**：宿主在 WebView2 就绪前丢弃页面消息
   （`post-page-skip reason=not-ready`），而插件首次推送必然落在那个窗口里。修复：收到宿主
   `ready` 后重发一次设置树。

**另外恢复的一处升级回归**：v0.4.12 重写配置同步时丢掉了「详细日志」旧值**写回** `diagnostics.json`
的那一步，导致老用户升级后该设置被重置、且改别的开关还可能把它翻回去。已改回走
`FoliaConfigGroups.readBoolean`（迁移的唯一所有者）。

**验证**：`verify-all.mjs` **10/10** 全通过；真机（SPW 1.19.3 + WebView2 150.0.4078.83）改配置后
**≤1 s** 内捕获推送，开→关→开双向即时生效；真机启动首次出现 `settings loaded (persisted)`
（此前 8 次启动全部回退到 `default`）。新增三个回归脚本：`verify-json-singleline.mjs`（10 项单元）、
`verify-playback-switches.mjs`、`verify-live-settings-payload.mjs`。

**已知问题（如实记录）**：`verify-layout.mjs` 的 `exitedZero` / `closedUser` /
`escClosedSettingsOnly` 三项在**快速 开→关→重开→ESC** 的极端时序下会失败，原因是上游
`StudioWindow` 卸载动效与 React 协调器的竞态（宿主日志可见
`NotFoundError: insertBefore/removeChild`）。真实单次「打开→关闭」实测 **0 报错、ESC 正常关闭面板**，
因此不阻塞发布。

**产物**：`spw-folia-0.4.13.spmod`，15,438,647 B / 3,982 项，`Plugin-Version: 0.4.13`，
权限 class-transform / library-read / key-bindings；宿主 exe 未改动（164,864 B），
WebView2 Runtime 实测 150.0.4078.83。
