# v0.4.20 更新日志

本次版本修掉 issue #21 的两项：设置页里**所有下拉菜单点了没反应**，以及按你的要求**把宣传站整个删掉**。

## 1. 下拉菜单点不动（已修复）

你报的是「字幕 → 第二行 / 第三行 那个下拉栏，无法切换翻译或者下一句」。查下来这不是字幕页的
问题，是**设置窗口里每一个下拉都点不动**，只是字幕这两行最显眼：

- 上一版（v0.4.19）新增了「副字幕行数 / 内容」，选「三行」后第二行、第三行各有一个下拉。
  点开时菜单**确实弹出来了**，但它画在设置窗口**背后**，用户看到的还是原来那一行，
  于是表现成「点了没反应、值也不变」。
- 根因是叠放次序：插件把整个设置窗口 + 播放页控件挂在一个注入容器里，这个容器带一个极大的
  `z-index`；而 Folia 自己的浮层（下拉菜单、弹窗、提示气泡）是挂到页面 `body` 上的**同级兄弟**。
  同级之间只有 `z-index` 大的赢，所以容器一旦高于 Folia 菜单的 `z-index`（200），
  **所有下拉菜单都被压到窗口背后** —— 菜单在 DOM 里、真的是打开的，但一个像素都点不到。
- 修法是把注入容器的层叠级别降到 100：Folia 页面内容最高只到 20，100 依然盖得住画面；
  而 200/205/210/220/300 这些浮层全部回到窗口上方，和桌面版 Folia 里的表现一致。
- 受影响的**不止字幕页**：歌词动画页的「歌词画布分辨率」、各样式面板里的下拉同样恢复了。
  播放页右上角齿轮、右下角菜单、底部播放条、样式画面点击分区都不受影响（已逐项复验）。

这一条加了发布闸门 `packaging/tools/verify-select-layers.mjs`：它不只检查「菜单在不在」，
而是用 `elementFromPoint` 判断**菜单中心与选项是否真的是点击目标**，并在真实宿主里点一次
「下一句」、确认设置值变了、并且新值确实进了下发给播放页的配置。把注入容器调回旧值，这个闸门
会红 4 项（已实测），所以这类「渲染了但点不到」不会再静默过闸。

> 教训记在 `docs/lessons.md` §4.1：注入岛是层叠上下文，上游浮层是它的 `body` 兄弟，
> 岛的 z-index 必须低于上游最大浮层。
